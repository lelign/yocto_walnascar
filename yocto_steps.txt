# 14_02         решение проблемы несоответствия CRC для файла u-boot.scr в boot после внесения измений
        про CRC все не так просто, при загрузке u-boot проверяет соответствие сохраненного в переменных u-boot значения CRC 
        с вычисленным значением CRC  для файла u-boot.scr из boot сектора sd карты, 
        и если они не совпадают, выдает в консоль сообщение <Bad data crc>
        и, соответственно, не применяет данные из u-boot.scr
        Переписал скрипты от Володи для возможности их использования в python3. К сожалению CRC для u-boot.scr после 
        запуска этих скриптов изменяется, применить их не получится
        варианты решения
                1 убрать проверку CRC для u-boot.scr в u-boot
                        изменил 35-37 cause error when bitbake -c compile u-boot-socfpga
                        do_configure:append:arria10() {
                                mkimage -C none -A arm -T script -d "${UNPACKDIR}/ethaddr-u-boot.txt" ${UNPACKDIR}/u-boot.scr
                        }
                        bitbake core-image-minimal <= OK
                        fter edit u-boot.scr message <Baad CRC data> appeared, changes not applyed

                        hit_any_key
                        setenv verify no
                        saveenv
        OK =>           after this if change ethaddr in u-boot.scr it will be applyed
                        file
                        /home/iru/poky-socfpga/build/tmp/work/*/u-boot-socfpga/*/build/socfpga_arria10_defconfig/.config
                        change CONFIG_CRC32_VERIFY=y to CONFIG_CRC32_VERIFY=n 
                        bitbake-getvar -r u-boot-socfpga PR >> set to 6
                        bitbake u-boot-socfpga <= OK
                        bitbake core-image-minimal <= OK
                        Bad data crc !!!
                        change all CONFIG_CRC32** to # CONFIG_CRC32** is not set
                        Bad data crc !!!
                        added patch 0001-change-in-tools-mtk_image-c.patch
                        Bad data crc !!! may be missed?
                        removed patch .0001-change-in-tools-mtk_image-c.patch

                        added patch 0001-change-in-boot-image-board-c.patch
        OK =>           УРА ПОЛУЧИЛОСЬ, Теперь можно редактировать u-boot.scr и писать туда как угодно и что угодно!!!
                     
                2 указать список допустимых CRC для u-boot.scr в u-boot, соответственно переписать скрипт проверки CRC в самом u-boot

                3 самый заморочный >> редактировать u-boot.scr так, чтобы результирующий CRC совпадал с исходным CRC
                        реализовал, не работает по причине того, что CRC алгоритм имеет разные реализации для u-boot и Python3. 
                        Получилось создать скрипт python3, который может перезаписать файл так, чтобы он соответствовал 
                        заданному CRC, может пригодится в будущем, сложил все в edit_crc_via_python

        Чтобы в Ubuntu 24.04 навсегда перевести параметр apparmor_restrict_unprivileged_userns в значение 0 
        (отключить ограничение на создание пространств имен для обычных пользователей), 
        выполните две простые команды в терминале
                sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
                        kernel.apparmor_restrict_unprivileged_userns = 0

                echo "kernel.apparmor_restrict_unprivileged_userns = 0" | sudo tee /etc/sysctl.d/60-apparmor-namespace.conf
                       kernel.apparmor_restrict_unprivileged_userns = 0
